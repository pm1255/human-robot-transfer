## 旧“时序 6D”实际是什么

6D 位姿指三维平移与三维旋转，可表示为 `T_camera_object(t)`；时序 6D 是同一物体的该变换随时间变化的轨迹，并对跳变、缺失、身份和重投影一致性做检查。它不是额外六个物体参数，也不应与单帧物体位姿拆成互不相关的两份标注。

共享聊天中存在两个不同来源：

- 早期 HumanEgo 页使用原始 Aria 中 obj1/obj2 的 180 帧 reference，聊天明确说它与展示的宽视角 RGB 未完全逐帧对齐，不能直接用于该视频的训练标签。
- 后续 EgoVerse 页明确使用 `temporal_pose6d_proxy` / proxy QC，4834 帧展示不等于恢复了可信米制物体 6D；记录只支持它是连续性检查与代理可视化。

当前源码快照没有找回对应 proxy 生成脚本，所以不能断言其具体深度假设、旋转构造或滤波参数。应保留为历史诊断，不能升格为真值。新方案统一保存“物体 6D 轨迹”，附带时序质检与来源标识。

## FoundationPose 接入

官方 `run_demo.py` 使用物体 mesh、RGB、深度、相机内参 K，以及首个有效帧的物体 mask。首帧执行 `register`，后续 `track_one`。官方也支持通过参考视图建立神经物体表示的 model-free 路线；这不意味着任意单张 RGB 即可直接获得可信尺度。

1. 语义与实例分割确定目标物体和稳定 ID。物体 bbox 可由同一实例 mask 的外接矩形派生，保存派生来源；bbox 不是 3D 姿态或接触证据。
2. 准备相机内参、对齐 RGB 的深度、物体几何及尺度。传感器深度和估计深度必须区分；只有 RGB 时需先估计并对齐深度/尺度，结果仍标为估计。
3. 首个可见、掩码可靠帧初始化，随后跟踪。遮挡、跟踪丢失与重新初始化分别记录；传播帧不标作直接观察到的帧。
4. 保存物体到相机变换；有相机轨迹时另存物体到世界变换，明确矩阵方向、坐标轴和长度单位。
5. 检查渲染轮廓与掩码吻合度、可见区域深度残差、平移/旋转跳变、物体对称性、身份切换与缺失跨度。平滑或低重投影误差本身不能证明三维正确。
6. 在网页增加物体 6D 轨迹层，展示模型轴/3D 框、遮挡与跟踪状态、逐帧质量和来源。当前先保持用户指定的六项模块。

建议输出：`frame_index`、`timestamp_s`、`object_id`、`T_camera_object`、可选 `T_world_object`、`pose_source`（初始化/跟踪/传播/重初始化）、`depth_source`、`scale_source`、有效 mask、可见性与质量指标。没有有效预测时存缺失状态，不用单位矩阵代替。

按用户决定只处理当前 T 恤。当前实现保留轮廓与逐帧深度表面；布料关键点、稠密对应、抓持点与接触仿真尚未实现。首次代理试验使用经复核参考帧的可见深度表面，不补造隐藏面；它是局部可见表面基线，不等同于 SAM 3D 完整网格。

## 参考 EgoMatrix 的正确范围

论文第 3 节和附录 A.1 直接采用 FoundationPose 初始化并细化物体位姿，结合相机运动传播与 SpatialTracker 的刚体运动候选。输入几何由手与物体分割、物体重建、MoGe-3 深度/内参、HaWoR MANO/相机轨迹构成，利用手部尺度先验做共同尺度对齐。严重遮挡时限制更新自由度或保留传播结果。

后续流程是：手物重建 → 接触引导的多起点位姿优化 → 局部接触与穿透修正 → 机器人重定向 → Isaac Lab 中 PPO 物理跟踪 → 从同一仿真状态联合渲染机器人和物体。背景处理中移除人的手臂以及被替换的物体，再合成模拟前景，保存视频帧与控制/状态的时间对应。

对当前工程，已有 HaMeR 可先作为手部初始化；它并不替代论文中的完整相机轨迹和接触重建。目标若是平行夹爪，应重新设计抓取中心、夹爪方向/开合、碰撞与接触目标；不能直接照搬针对灵巧手的关键点映射。机器人需要满足关节限位、可达性、接触保持与任务成功，最后才生成成对视频和动作。

优先修正物体和机器人之间的真实几何/动力学关系，再渲染图像。仅抠掉人手并贴上机械臂不能保证夹爪接触或物体运动与动作一致。

## 当前实现与验收口径

- `sam3_video.py`：原始逐帧缓存和模型来源记录；早期文本跟踪结果已判为不可发布。
- `adaptive_segment.py`：逐帧检测棕色桌面区域，利用低饱和衣物区域提供 SAM3.1 实例提示框；通过实例分割头推理并读取单帧传播输出。最终像素由 SAM3.1 输出，框从掩码生成，无掩码插值。小区域、邻帧变化和接近提示边界的结果留复核标记。该定位规则专用于当前视频，不保证适用于其他场景。
- `depth_video.py`：MoGe-3 ViT-L，每帧估计深度与内参，3 次细化；保存 FP32 深度、有效像素与相机矩阵，米制尺度仅为模型先验，未与 HaMeR 或实测尺度对齐。
- `foundation_cloth.py`：固定可见表面参考网格；输出 rigid_object=false、pose_type=cloth_global_proxy。未通过轮廓 IoU（0.45）、相对深度残差（0.08）或逐帧跳变筛查的变换只存候选，正式 T_camera_object 留空。这些阈值是实验筛查参数，尚未用独立真值验证。
- `publish.py`：只有 SAM 与渲染状态完成、源视频哈希一致、4834 帧全部 mask/box 一致且两条视频逐帧解码成功时，才更新原网页资源清单。模型精度不会因为文件完整就判定通过。

程序检查：会话适配 2 项回归检查通过；投影、网格空洞保留及错误位姿拒绝 2 项检查通过；3 帧合成 mask 渲染通过。上述均为程序检查，不是实际分割或三维精度验收。

## GPU 试验与数值精度修复

MoGe-3 官方权重 SHA256 已核验。FlexGEMM 使用 MoGe 指定的 `b2fadb29d41846c7981ade6801ffc689fae119cf`，Triton 3.3 兼容修复保存在 `tools/prepare_flexgemm_compat.py` 与 `flex_compat.py`。9 项 GPU hash、去重和邻居索引计算与独立 Python 实现对照一致。这仅验证适配正确性，不验证深度精度。

FoundationPose 使用官方 refiner/scorer 权重和经图像检查的第 30 帧可见深度表面，顶点颜色来自原始 RGB。关闭 AMP 与 TF32 后，前 180 帧中参考帧起的 150 帧通过当前一致性筛查，前 30 帧保留参考帧之前状态。旧半精度/TF32 试验的旋转误差已留档，不能将其拒绝数归因于真实跟踪错误。

全片中折叠与遮挡会导致固定网格不匹配。失败后每 30 帧尝试重新注册，中间保留 `waiting_for_reinitialization`；所有帧仍保留 mask、深度、可见表面中心与范围。缺失位姿不插值，`T_camera_object` 留空。最终 2507 帧通过实验筛查，77 帧拒绝，2150 帧等待重初始化，70 帧输入不足，30 帧在参考帧前；完整限制以结果汇总为准。
