# 人类视频是否被用起来：实验与资源协议

## 已实现的最小训练实验

`scripts/train_pilot.py` 是小型 CNN 视觉模型，不是完整 VLA。输入前一帧和当前帧 RGB，共享视觉编码器；它用于验证数据进入模型、产生梯度、更新表征、并能迁移到机器人动作拟合。这是启动大模型训练前的验收，不能代替最终实验。

| 条件 | 人类预训练目标 | 作用 |
|---|---|---|
| scratch | 无 | 直接 RoboTwin 微调基线 |
| explicit | 预测未来二维捏合中心和开合变化 | 检验显式结构化运动监督 |
| shuffled | 相同输入、同分布的运动标签被置乱 | 排除只因额外步骤/标签分布而改善 |
| implicit | 预测未来低分辨率图像相对当前图像的残差 | 最小无显式运动标签视频学习基线 |
| hybrid | 同时预测上述运动和图像残差 | 验证二者能否组合 |

“implicit”在这里特指简单未来图像预测，不代表所有隐式人类视频方法，更不是最优潜在动作模型。图像残差和运动损失单位不同，hybrid 的默认等权只是通路验证配置；最终比较需匹配梯度尺度或扫描权重。

人类数据只用二维标签，不需要把错误的米制轨迹硬塞进 action。窗口要求过去/当前/未来帧都可见且同一 track，遇到缺失或身份切换就拒绝。每个条件使用相同窗口、初始化、随机种子、采样序列、优化器与步数；任务文本暂不输入这个小模型，因此不得称其已经完成语言条件学习。

每个条件记录样本曝光次数、被看到的唯一窗口数、编码器梯度、训练前后权重哈希、参数变化 L2。人类数据“参与计算”由这些证据证明；“有用”需要额外的留出集和闭环评测。训练集 loss 下降不能证明泛化。

## RoboTwin 小样本微调

本次从既有 RoboTwin `adjust_bottle` 的 LeRobot v3 数据读取前 10 个 episode，0–7 为训练、8–9 为验证，每两帧取一个样本，但上一帧观测仍使用原片紧邻帧。只解码 head_camera；保留原始 14 维 `observation.state` 和 `action`，不误用 16 维 `action_eef`。

视频通过 meta/episodes 中的文件索引和 from_timestamp 定位，验证 frame_index 连续及时间差符合 15 FPS，再用 ffmpeg 解码 RGB。采样之前不拼接 episode；归一化统计只用训练集。源目录只读，所有派生产物写入自己的实验目录。

五个条件微调时迁移视觉编码器，机器人动作头统一重新初始化，机器人样本与步数完全相同。报告验证集标准化 MSE、每维原生单位 MAE，并比较训练动作均值、保持当前状态两个基线。图像置乱/置零诊断用于发现模型是否只抄当前状态。关节角与夹爪源单位混合的总体 MAE 不能写成“几毫米误差”。

当前只做离线 action fitting，没有运行仿真控制器。若保持当前状态已比模型更好，或者置乱图片不影响误差，应明确认为这个离线指标不足以证明视觉学习收益。

## 正式 VLA 实验如何设计

第一阶段固定一个基础 VLA、同一机器人动作契约和同一视觉前处理；接入人类辅助 head，机器人 action loss 只作用于真正有动作的机器人样本。可采用人类预训练后机器人微调，也可混合训练；两阶段不是必需条件。缺失人类指令可仅用视觉任务训练，或生成带来源的描述，不能假装原始视频自带精确任务。

第二阶段比较五组：机器人-only；纯视频目标；显式二维/三维运动；可执行重定向参考；隐式+显式。再加入置乱人类标签、时间倒序/错位、去掉人类、冻结视觉编码器等消融。对照至少 3 个随机种子，固定模型、总优化步数、机器人曝光量；另提供等总图像量/计算量对照。显式路线比隐式路线多用的估计模型和标注成本也需统计。

表征差异不能只看 t-SNE。冻结编码器做动作阶段、物体相对位移、接触候选线性探针；在未见场景/物体/人上测误差；用 CKA 等比较表示变化；最后看同等机器人样本数下的闭环学习曲线。显式表示可能更强调几何但受伪标签偏差影响；隐式表示可能保留更多外观/时序信息但不保证控制相关。这是待检验的假设，不是本轮训练结论。

## 能否替代其他真机数据集

需要区分替代“预训练数据中的一部分”与替代“目标机器人的所有示教”。人类视频没有目标控制器的真实响应、夹爪力和时延信息；后者不能从离线重定向自动获得。

建议设目标机器人示教量为 10/25/50/100%，人类数据量为 0/固定池/扩展池，画闭环成功率对数据量曲线。固定测试集和初始化场景，按任务、对象、场景分层，给出 Wilson/Bootstrap 区间。预先规定非劣容差，例如成功率差不低于 −5 个百分点，然后检验“50% 机器人示教 + 人类视频”是否在足够统计功效下不劣于“100% 机器人示教”。5pp 只是实验设计示例，需按任务成本确定。

RoboTwin 是仿真基准，不是真机数据。[官方集成说明](https://huggingface.co/docs/lerobot/robotwin) 将其与 SAPIEN 评测连接。RoboTwin 成功最多支持仿真内的数据效率结论；要声称替代真机数据，必须在目标实体机器人、独立对象/场景和可重复控制器上再评测。也不能用仅一项 adjust_bottle 的结果代表全部任务。

## 上线门槛

1. 数据门槛：来源与任务可追溯，时间/相机/尺度状态明确，来源级划分无泄漏。
2. 几何门槛：独立标注抽检及失败率、真实 robot URDF/TCP、碰撞与接触验证。
3. 训练门槛：有效样本数与 loss mask 正确，数据确有曝光与梯度，不发生 NaN 和未来信息输入泄漏。
4. 闭环门槛：策略载入、reset、图像通道/单位、控制动作语义和频率通过单 episode smoke，再扩大评测。
5. 决策门槛：至少多种子、留出任务/对象/场景及置信区间，才能讨论隐式/显式优劣和数据替代率。

当前任务的实际完成状态以 `outputs/` 中运行日志、`web/data/training.json` 和原生导出验证报告为准；本协议不能代替运行结果。
