# 从人类 RGB 视频到可训练参考轨迹：工程方案 v0.1

本文同时说明目标方案和本次代码的实际边界。目标机器人首先是两指夹爪机械臂。人类侧只读取 RGB 视频，不读取动捕服、手套、遥操作设备或采集硬件记录的动作。真实机器人数据中的状态、动作可以用于后续适配和评测。

最重要的区分是：**视频估计的人体运动、重定向得到的机器人参考运动、机器人实际执行的控制命令，是三种不同的数据。** 换一个字段名不能让第一种变成第三种。模型能输出一个三维数值，也不等于这个数值已经具有正确的米制尺度。

## 1. 数据产品与准入层次

| 数据层 | 记录什么 | 可以训练什么 | 不能据此声称什么 |
|---|---|---|---|
| R0 原始证据 | 视频、时间戳、来源、许可、原始任务文本 | 视频表示、未来图像/潜变量预测 | 有机器人动作标签 |
| R1 图像标注 | 手/人/物体的二维位置、身份、遮挡、文本来源 | 关键点、运动、交互事件辅助任务 | 得到米制世界运动 |
| R2 三维参考 | 相机轨迹、手/物体姿态、尺度状态、协方差/置信度 | 几何辅助任务、物体相对运动 | 已经可执行 |
| R3 重定向参考 | 指定机器人 URDF、TCP、关节参考、可达性 | 通过掩码筛选的参考运动监督 | 等同实测状态或控制命令 |
| R4 执行示教 | 仿真/机器人实际观测、发出的动作、成功与失败 | 机器人行为克隆、VLA action loss | 仿真成功等于真机成功 |

本次原型实现 R0、R1、部分 R2/R3；合成案例有程序真值。真实 EPIC 视频尚缺独立尺度、运动相机恢复、物体接触核验，所以机器人动作准入为零是正确行为。低层不合格不必丢弃整个视频：例如 R3 不合格的视频仍可用于 R1 的二维运动辅助学习。

## 3. 步骤一：先确定视频是什么，再抽帧

先检查画面确实有人手/人体操作，而不是机器人、动画、剪辑拼接或旁观视角。文件名不能完成这项判断。本次 `rovid_*` 两段抽帧后发现是机器人视频，保留为网页反例。

保存源集群、源路径、源文件/裁剪片段哈希、原片 episode ID、裁剪起止、转码参数、视频 PTS、原始描述及其来源。上游 VLM 描述只能标记为 `task_source=upstream_vlm_caption`，不能说是采集者给出的指令。没有任务文本的视频仍能学习视觉时序；要做语言条件任务，需补人工/模型描述并分别记录来源。

本次 8 段 EPIC 裁剪，每段最多 7 秒，10 FPS、宽 640。转码是便于验证的轻量视图；源路径保留。不是把每十个原始帧简单认为相隔一秒，解码必须核查 PTS。可变帧率转固定帧率要保存映射。

训练、验证、测试按原始长视频/session/person 分组。切片不能随机分组，否则同一厨房、同一人、同一动作会泄漏。本次暂未解析原始 session，8 段统一放入一个保守组，不报告人类视频独立测试集准确率。

## 4. 步骤二：关键点到底是什么，左右手如何处理

关键点模型看一张图，输出固定语义位置：例如 MediaPipe 的 0 是手腕，4 是拇指尖，8 是食指尖，5 和 17 是食指/小指掌指关节。它不是在图上寻找一个唯一的亮点，而是根据大量图像学到“这种视觉结构更像某个关节”。遮挡时也可能给出位置，因此“有坐标”不能等同“看到了”。[官方模型说明](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)

本次每帧检测至多两只手，再按相邻帧手腕距离关联一条活动手轨迹。手消失后重新出现，会开启新的保守 track，防止跨身份插值。模型给出的 left/right 单独保存；镜像未知时不认为左右手经过验证。这版是最小关联器，不足以处理两手交叉、同位置替换等复杂情况。正式版应结合外观、腕/肘连接、速度预测、遮挡历史，并在交叉区允许身份不确定。

左右手语义是人的解剖学左右，不是图像左边/右边。必须记录视频是否被镜像；若做水平翻转增广，二维 x、相机内参/变换、左右手语义和动作坐标要成套变换。单独翻图片会制造错误监督。

关键点有三个用途：给三维拟合提供观测；定义手的朝向/指间开合候选；做重投影和时间一致性质检。它不直接给出机械臂每个电机要转多少。

## 5. 步骤三：从局部三维到相机轨迹，再到世界轨迹

MediaPipe 的局部三维点含有学习到的手形尺度先验。本次用 SQPnP 求一个旋转 R 和平移 t，使这些三维点投影后接近检测到的二维点：`min Σ ||project(K, R X_j + t) − u_j||²`。默认焦距是假设值，输出标记 `metric_estimated`，不是标定真值。重投影误差小只能证明这组估计自洽，不能排除尺度和深度一起错。

相机移动时，同一个世界点在图像上也会动。需要 `T_world_camera(t)`，才能计算 `p_world(t) = T_world_camera(t) · p_camera(t)`。统一规定 `T_A_B` 将 B 系点变换到 A 系；坐标右手系、长度米、旋转为合法 SO(3)。矩阵乘法顺序需要数值测试，不能靠字段名猜。

SLAM 与手部单目重建解决的问题不同：SLAM 借静态背景估计相机运动；手部模型借人体先验估计动态手。操作视频运动小不总是更好：纯旋转或很小平移缺少视差，深度/尺度更难恢复；手和物体占满画面、运动模糊、反光台面又会破坏静态假设。第一视角低头和转身也可能很大。本次原片确有移动相机，因此默认单位相机矩阵只用于演示，绝不称作已完成 SLAM。

正式恢复建议：标定或估计内参 → 检测/分割人手和活动物体 → 对背景追踪特征并做相机束调整 → 检查视差、重投影残差和回环 → 用已知尺寸物体/桌面几何等视觉尺度锚恢复米制 → 将手、物体都变换到统一世界系。这里不能使用被禁止的采集硬件动作标签。

尺度锚也不充分时，保留 scale-free/estimated 状态。只要任务允许，可训练二维或物体相对运动；不要默认人的手长相同。固定相机只能在有证据时启用，并记录证据。

## 6. 步骤四：修复究竟优化什么

有三种不同变量：图像关节点 `u`、人体模型参数/三维关节点 `X`、机器人关节 `q`。它们可以分层优化，也可以联合优化，不能混称一个“关节优化”。

本次代码先把手点变成候选 TCP 位姿，再优化其**三维平移** `p_t`；原始检测点不被覆盖。目标是测量一致性加时间加速度惩罚，低置信度点权重小，对孤立的大跳变强降权。采用实际 `Δt` 计算速度/加速度，旋转缺失以 SO(3) SLERP 插值。短缺失必须两端有效、同一身份和阶段、时间跨度不超过 0.25 秒；长缺失保留无效。当前不具备从长遮挡凭空恢复真实动作的能力。

完整人体版本可优化 MANO/SMPL 参数：`L = L_2D重投影 + L_观测3D + L_时间 + L_骨长/关节限位 + L_物体接触 + L_非穿透`。相机、尺度也可以成为变量，但应固定一个世界参考系以消除自由度。所有项使用可信度/协方差加权及鲁棒损失。

为什么不能只平滑：平滑能让错误轨迹很好看，却会抹掉抓取瞬间或将手平滑进桌面。为什么不能直接强制接触：如果接触标签猜错，强约束会把原本正确的手拉到错误物体上。每个修复都要记录原始值、修改量、原因、使用了未来帧、优化是否收敛。离线平滑用了未来信息，不能宣称同样的质量可实时取得。

本次门槛（如 0.25 秒、厘米级跳点）是原型配置，不是行业标准，必须用真实标注抽检集按动作类型校准。

## 7. 步骤五：人手如何换成两指夹爪

人手的五根手指不会逐根映射成机器人手指。我们先提取“抓哪儿、从哪个方向接近、两侧夹多宽”。最小候选如下：

1. 拇指尖与食指尖的中点作为候选夹持中心 c。
2. 从拇指尖指向食指尖作为夹爪闭合轴 x。
3. 手腕到掌指关节中部提供接近方向参考，剔除其沿 x 的分量并归一化为 z。
4. `y = z × x`，再检查右手系和退化情况，组成 `T_camera_grasp`。
5. 两指尖距离给夹宽候选；它不是夹爪电机命令，更不是抓取力。

手指几乎重合、掌面向量退化、遮挡、拿工具、全掌包握都可能使这个候选错误。正式版应使用物体网格/点云选择可夹的相对表面，检查夹爪厚度、开口、接近路径和接触法向，再把“人如何抓”作为偏好而非硬复制。

**换成夹爪之后仍然需要优化。** 第一轮优化夹持中心、方向、接触点和开合宽度，使候选适合机器人夹爪；第二轮求机器人关节 q，使其 TCP 到达该候选。若不可达，可在物体允许范围内回调候选再求 IK，而不是只盯着电机关节硬凑。

例如人捏住杯子把手，机器人夹爪太宽：直接复制两指中点会碰杯身。应尝试杯身两侧抓取或放弃该样本，而不是把 IK 成功当成任务成功。对于切菜、搅拌等工具操作，需要工具坐标系和稳定工具—夹爪关系，本次候选器尚不能验证这些动作。

## 8. 步骤六：重定向的第三、第四环节具体在算什么

先知道物体在哪里，才能将“人相对物体怎么动”移到机器人场景。源抓取姿态为 `T_world_grasp`，源物体为 `T_world_object`：

`T_object_grasp = inverse(T_world_object) @ T_world_grasp`

目标机器人场景物体姿态为 `T_robot_object`，夹持中心到机器人 TCP 的固定标定为 `T_grasp_tcp`：

`T_robot_tcp_target = T_robot_object @ T_object_grasp @ T_grasp_tcp`

这意味着物体转了 90°，接近方向也跟着转，而不只是给位置加个偏移。本次 `transfer_object_goal` 有旋转和工具偏移测试，但真实 EPIC 未估计物体位姿。网页对真实片段使用首帧对齐到机械臂可达位置，只演示几何转换，带 `ILLUSTRATIVE_ROBOT_ALIGNMENT`，不能用于真实动作准入。

然后做逆运动学：URDF 规定每个关节轴、父子关系、连杆长度和限位。FK(q) 算 q 对应的 TCP 位姿；IK 反过来找 q，让位置与姿态误差小，并尽量接近上一帧关节。形式为：

`min_q ||p_FK(q)-p_target||²/σp² + ||log(R_target R_FK(q)^T)||²/σR² + λ||q-q_prev||² + 碰撞代价`

约束 `q_min ≤ q ≤ q_max` 和 `|q-q_prev| ≤ velocity_limit·Δt`。本次检查限位、速度、末端误差及连杆对球/平面的碰撞代理。优化求解结束仍要检查残差；不可达不是把最近点标成成功。有效片段间断开时要重新规划连接，不能把 reset 后的第一帧与上一段直接连播成连续指令。

当前示例臂是教学 6DOF 模型，不是 Aloha。实际换机器人时需供应真实 URDF、TCP、base/world 外参、夹爪开合标定、碰撞几何、控制模式与频率。具有 mimic/闭链的模型不能默默按普通串联关节处理。完整执行前还需自碰撞、加速度/力矩和控制器跟踪验证。

## 9. 步骤七：交互关系和事件边界

这不是仅靠一种路线才能用的附加标签。二维路线可以输出“手靠近杯子”的弱关系，三维路线可以增加表面距离和法向，带物体模型的路线可以检验接触。信息层次不同，但共享事件协议。

建议每帧输出图边：`(hand_track_id, object_track_id, relation, score, evidence, coordinate_frame)`。关系包括 near、touch_candidate、grasp_candidate、carrying、release、unknown；证据包括二维接近、三维距离、物体随手共同运动、开合变化、遮挡。视觉通常不能直接证明力闭合或接触力。

例如 grasp 不能只看两点很近：先有接近，再持续近距离，夹宽下降，随后物体与手近似刚性共同运动，才提高置信度。释放则结合开合增加、物体不再随手移动、物体由桌面支撑。把单帧判断送入带最短持续时间和迟滞的状态机/HMM，减少来回跳变；保留边界区间 `[最早可能帧, 最晚可能帧]`，不要假装准确到某一帧。

正式质检需要人工双人标注小集，报告边界容差下 precision/recall、事件段 IoU、未知率和争议率。训练时边界缓冲区可屏蔽接触损失；动作 chunk 不跨任务/身份边界，是否允许跨同任务内部阶段应按目标模型定义。本次保守禁止跨 phase，并将真实自动阶段设为 unknown，未声称实现自动事件检测。

## 10. 步骤八：如何验证标注真的可用

必须分别回答四个问题：标注是否与视频吻合？重建是否具有正确几何？机器人能否执行？学习是否受益？单个小误差不能替代这四层验证。

| 验证 | 本轮/目标做法 | 可以得到的结论 |
|---|---|---|
| 证据层 | 抽帧可视化、关键点叠加、镜像/身份核对、时间对齐 | 没读错素材、知道标注失效在哪里 |
| 数值层 | 有真值的合成相机/尺度/跳点/缺失/旋转压力测试 | 代码公式和门控是否正确；不代表真实模型精度 |
| 几何层 | 独立人工2D、已知物体尺寸、多视角验证集、重投影 | 真实标注误差分布；不能只用参与拟合的点自证 |
| 可执行层 | 真实URDF、物体接触、碰撞与动力学、控制器 rollout | 重定向参考是否可被目标机器人跟踪 |
| 学习层 | 同预算对照、打乱标签、去掉人类、闭环成功率 | 人类数据是否产生可迁移收益 |

网页既显示成功也显示失败，保留 raw/repaired/target/FK 的不同颜色。IK 误差只是“这台模型臂是否跟上候选”，不衡量候选是否等于人真正的手。零动作准入样本不能通过降低门槛变成可执行样本。

## 11. 统一坐标和字段能否作为修复约束

可以，但必须分清“单位/坐标转换”和“新增观测约束”。把厘米换成米、把点乘上已知外参，是确定性变换；它能发现尺度相差 100 倍、轴反向、左右手错配。已知桌面平面、已知骨长范围、同一刚体的多个观察则可以真正增加约束。只是把所有字段都命名为 world，不会消除深度歧义。

核心字段保存 episode/time/source、units/frame、T_world_camera、关键点/姿态、observed、confidence_semantics、track_id、phase、scale/camera/mirror/grasp_status、修复掩码、机器人模型版本、IK 误差和失败原因。旋转接口以矩阵为主，输入四元数需显式顺序并归一化。反射矩阵必须拒绝，不能当旋转矩阵。

输出分两个训练视图：人类辅助视图包含 RGB、二维/三维参考及掩码；机器人视图只有通过执行契约核验的数据才能给 action/state。未观测值写 null/NaN 于审计层，训练张量 finite-fill 后**必须同时传 mask**。

LeRobot 使用官方 writer/loader 进行导出和读回，不能自行放几份 Parquet 就称兼容。本次人类视图采用自定义 `annotation.*` 字段，无虚构的 `observation.state` 和 `action`；标准机器人 BC 脚本不应不加修改直接读取。原生参考 NPZ 明确不是 LeRobot。[LeRobot v3 官方说明](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)

## 12. 接入现有转换、质检、清洗和配比

本次新建独立模块，不直接重写已有转换器。接入顺序为：转换器输出统一中间契约 → 质检器输出逐帧/段掩码与原因 → 修复器生成新版本及修复差异 → 重跑质检 → 导出各训练视图 → 按任务/质量/来源采样。

必须保留拒绝原因分布和采样日志。高质量样本少不能单纯重复到训练中占比极高；按独立 episode/session 权重而不是帧数配比。人类帧、机器人帧的损失单位不同，既记录批次比例，也记录 loss 权重、有效监督 token、实际曝光次数。机器人 action loss 不应用在人类标签缺失处；未知值绝不能填零后参加 action loss。

后续可比较 0/10/25/50% 人类辅助批次，固定机器人数据量、优化步数和总图像量各做一组控制。不要同时换模型、增训练量、加人类数据，再把收益全部归因于人类视频。

## 13. 与 Light-O1 的关系

本地核查的 Light-O1 README 描述结构化人类动作先验及后训练，其输出是统一人体动作表示；这不能直接证明它提供完整的“任意第一视角操作视频→两指夹爪执行轨迹”工具链。我们采用相同的基本分层思想——先人类表示，再 embodiment 适配——但不把人体关节表示强制伪装成机械臂动作。[原始仓库](https://github.com/lightorigins/Light-O1)

下一阶段先补最薄弱的尺度/相机/接触证据，再决定哪些样本进入机器人参考监督，而不是先放大训练规模。
