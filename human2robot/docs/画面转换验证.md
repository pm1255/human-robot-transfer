# 人变机器人、手变机械臂：目前交付范围

网页“画面转换”提供 8 段手部、4 段全身的三栏对照视频：原始 RGB、启发式删除掩码、填补背景并渲染机器人后的 RGB。它们是几何预览，全部 `training_eligible=false`，没有进入已完成的八个策略实验。

## 两条转换路径

手部：读取 v1 人手修复目标 → 用首帧对齐放入 Aloha 工作区 → 按 RoboTwin Aloha / AgileX ARX5 的真实 URDF 重新求解 IK → 根据相同 URDF 做各连杆和夹爪 FK → 渲染真实型号的表面网格，投回假定相机。9 个连杆网格保留形状并减面至每个最多 3,500 个三角形，材质采用近似金属色，未使用原始纹理。没有复用参考臂关节值。夹爪滑块使用人手估计间距的一半并限制在 URDF 行程内，不等价于校准后的指尖间距。仿真 URDF 关节范围很宽，不能作为硬件安全范围。

网页“02”左边原视频，右边 WebGL 实体模型，可以旋转、缩放、切换正面/侧面；橙色球框为目标，蓝色球为实际 TCP。默认不显示空间轨迹，仅通过开关展开。关节曲线每次看一个关节，使用度和秒，附有图例和当前时刻游标。

全身：MediaPipe 的身体局部 3D 点 → 正旋转转换坐标轴 → 保留骨段方向、改用 G1 骨长 → 有关节上下限的逐帧最小二乘 IK，位置误差加软时间连续项 → MuJoCo 正运动学 → CPU 深度缓冲栅格化原始 CAD 表面网格（减面、平滑顶点光照、2 倍抗锯齿） → 用二维点拟合弱透视相机放回原画。根平移固定为零，图像平移由投影承担，因此没有恢复可执行的世界根轨迹。没有碰撞、地面接触、平衡或动力学保证。

两者均用 OpenCV Telea 单帧填补背景；没有扩散或视频生成基座、没有训练权重，训练步数为零。G1 的数值 IK 迭代不属于模型训练。G1 XML 和网格只读引用 `work/Light-O1/examples/sonic/assets/g1`，资产授权见该目录的 `LICENSE`，没有修改来源资产。

## 怎样检查、检查能证明什么

每段视频有逐帧 JSON：来源 SHA256、关节、拟合误差、删除像素数、渲染像素数和训练拒绝标志。缺失预测帧保持原画，不伪造机器人。

`v2.audit_conversion` 逐帧解码视频，核对帧数与时间，检查 G1 关节范围和四元数，并从关节重新算 FK 拟合误差。渲染器还在加字幕和有损压缩前核对：掩码与机器人之外的像素不变。拟合误差的目标也是预测的人体，误差小只说明拟合一致，不证明人体 3D 正确。

可见缺陷包括帽子/衣物边缘残留、补背景闪烁、物体可能误删、机器人与工具接触不准、深度遮挡错误。必须人工检查中间掩码与右栏；当前没有分割真值、深度真值或动作成功率来证明合格。

## 复现

从 `human2robot` 目录，使用项目虚拟环境（需 render 可选依赖、ffmpeg 和上述本地 G1 资产）：

```sh
../.venv/bin/python -m v2.build_aloha
../.venv/bin/python -m v2.audit_aloha
../.venv/bin/python -m v2.render_conversion
../.venv/bin/python -m v2.audit_conversion
../.venv/bin/python -m v2.build_experiment_card
```

## 与训练结果的关系

现在完成的是“源视频 → 几何转换展示”，以及另一条“原人类视频辅助监督 → 小型视觉 BC”的实验。不是“转换视频 → 完整 VLA”。把两者接上仍需相机/尺度估计、分割跟踪、物体深度与接触验证、统一目标机器人、同步有效动作标签，再做转换数据加入前后的同基座训练与闭环比较。

尤其不能用当前 32×32 未来 RGB 残差头充当人变机器人的重建模型；也不能用两个不同损失的大小证明显式或隐式更好。最终应报告相同 RoboTwin 任务场景上的成功率、动作偏差与执行视频。
